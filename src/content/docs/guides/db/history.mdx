Db keeps every edit. Each one adds a row to the edit history, and each row
points to the one before it. Walking that chain backwards is undo, walking
it forwards again is redo.

<UsecaseRevision />

The figure shows how a catalog changes from one year to the next, and how
everything else stays. The edit history works the same way: every step
builds on the step before it.

You will learn how to:

- read the edit history of a cake
- follow a history row to its edit
- go back to an earlier edit and forward again
- edit after going back

## What you have learned

- Every edit adds a row to the edit history of its cake.
- A history row points to its multi edit and to the row before it.
- `editHistoryRef` moves the head of a manager to any step.
- Undo and redo are a walk back and forth along the history.
- An edit after going back starts a branch; the later edits stay.
- A later `setValue` on the same cell replaces the earlier one.
