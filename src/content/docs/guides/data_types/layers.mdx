A layer assigns a component to each slice of a set, like a layer of a cake
that is cut into slices. The slices are named by slice ids. The slice ids
live in a table of their own, and the components in a components table. The
layer maps each slice id to the hash of a component.

In this tutorial you build a recipe book. The slice ids are the ingredients
of a recipe, like `flour` and `sugar`, and the components are amounts, like
250 g. Each recipe is a layer. You create a sponge recipe first, and then
derive a butter cake and a gluten-free sponge from it.

You will learn how to:

- list slice ids in a `sliceIds` table
- create a layer that assigns components to slice ids
- derive slice ids and layers from a base, with `add` and `remove`
- resolve the assignments of a derived layer

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir recipe-book
cd recipe-book
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `recipes.ts`. Each of the following steps adds code to it:
put the imports of a step at the top of the file, and its code below the code
of the previous step. The complete file is shown at the end.

A row of slice ids has three fields:

| Field    | Meaning                                             |
| -------- | --------------------------------------------------- |
| `add`    | The slice ids of the row                            |
| `base`   | Optional: the hash of a row that this row extends   |
| `remove` | Optional: slice ids of the base that this row drops |

Keeping the slice ids apart from the data pays off with large layers: a
client can fetch the slice ids first and load the components only for the
slices it needs.

## 4. Create a layer

The sponge recipe is a layer. It assigns an amount to each of its slice ids:

<Snippet
  file="layers.spec.ts"
  region="layer"
  title="recipes.ts"
/>

| Field              | Meaning                                                    |
| ------------------ | ---------------------------------------------------------- |
| `sliceIdsTable`    | The name of the table with the slice ids                   |
| `sliceIdsTableRow` | The hash of the row in that table that lists the slice ids |
| `componentsTable`  | The name of the table with the components                  |
| `add`              | Maps each slice id to the hash of a component              |
| `base`             | Optional: the hash of a layer that this layer extends      |
| `remove`           | Optional: assignments of the base that this layer drops    |

A layer refers to tables by the names they will get in the Rljson object,
and to rows by their hashes. Like other rows, a layer may have an `id`; here
it names the recipe.

A derived layer stores only what differs from its base. It follows one rule:
it assigns a component to every slice id that its own row of slice ids adds.
The butter cake adds `butter`, so it assigns an amount to `butter`.

## What you have learned

- A row of type `SliceIds` lists slice ids in `add`. It can extend a base row
  and remove slice ids from it.
- A layer names its table of slice ids, its row of slice ids and its
  components table, and assigns a component to each slice id in `add`.
- A derived layer extends a base layer with `add` and `remove` and stores
  only the difference.
- Equal components are stored once, however many slices use them.
