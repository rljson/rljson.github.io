`@rljson/edge` creates test data for Rljson applications: a car world
with manufacturers, their catalogs and cars. Every car has a price, a brand,
a workshop, a bill of materials and a CAD scene. The world uses every data
type of the [Data Types](/guides/data_types/components/) tutorials, so one
generated world exercises components, slice ids, layers, cakes, trees,
revisions and table configurations at once:

```text
Manufacturers            components   manufacturers
└─ Catalogs              jsonArray    manufacturers.catalogsRef
   └─ Catalog            cakes        catalogs, its slices are cars
      ├─ Prices          layers       carPrices    → components  prices
      ├─ Brands          layers       carBrands    → components  brands
      ├─ Workshops       layers       carWorkshops → components  workshops
      ├─ Parts           layers       carParts     → components  parts
      └─ CAD             layers       carCad       → trees       cadScenes
```

In this tutorial you generate the smallest world, list its tables, validate
it and generate it a second time to see that nothing in it is random.

You will learn how to:

- generate a world from a preset with `Edge.preset`
- read the tables of a generated world
- validate generated data with `BaseValidator`
- read the statistics of a run
- reproduce a dataset from its configuration alone

## 1. Set up the project

Create a project and install the generator and the core package:

```bash
mkdir car-world
cd car-world
echo '{ "type": "module" }' > package.json
pnpm add @rljson/edge @rljson/rljson
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `first.ts`. Each of the following steps adds code to it:
put the imports of a step at the top of the file, and its code below the code
of the previous step. The complete file is shown at the end.

## 2. Generate a world

A preset is a complete configuration. `tiny` describes one manufacturer with
one catalog of five cars. A second argument would override any part of it:

`generate` builds the world in memory and returns it together with the
statistics of the run. The world is an Rljson object: its keys are the
names of the tables.

| Preset   | Manufacturers | Catalogs each | Cars each | For                         |
| -------- | ------------- | ------------- | --------- | --------------------------- |
| `tiny`   | 1             | 1             | 5         | Unit tests, this tutorial   |
| `small`  | 2             | 2             | 100       | Component tests             |
| `medium` | 5             | 4             | 5 000     | Integration tests           |
| `large`  | 10            | 10            | 2 000     | 25 million rows, load tests |
| `xl`     | 20            | 20            | 50 000    | 20 million cars             |

<Aside type="note">
  `generate` keeps the whole world in memory. That is fine up to `medium`. For
  `large` and `xl`, [Generate large datasets](/guides/generate/large-datasets/)
  hands the rows to a callback instead.
</Aside>

`BaseValidator` checks the hashes, the references, the layers, the cake and
the trees, as the Data Types tutorials describe. The generator
writes a [TableCfg](/guides/data_types/table-cfg/) for every table into
`tableCfgs`, so the validator checks the types of all columns and every
reference, too.

## 6. Reproduce the data

Edge draws no random numbers. Every value derives from an index into a
dictionary: the first manufacturer is the first entry, the model of a car
derives from its number, a share selects every k-th car. So the same
configuration yields the same rows, and the same hashes, on every machine:

<Snippet
  file="first-dataset.spec.ts"
  region="reproduce"
  title="first.ts"
/>

The hash of the catalogs table covers every catalog, and through the
references every layer and every component. If it is equal, the worlds are
equal. Another configuration yields another world.

<Aside type="tip">
  A test that fails on a generated world fails on the same world every time, and
  a golden file of the world stays stable until you change the configuration.
  There is no seed to fix.
</Aside>

## What you have learned

- `Edge.preset` creates a generator from a preset, and a second argument
  overrides parts of it.
- `generate` returns the world as an Rljson object and the statistics of the
  run.
- A generated world is ordinary Rljson data, with a TableCfg for every
  table, and `BaseValidator` validates it.
- Nothing is random: the same configuration yields the same data and the
  same hashes.
