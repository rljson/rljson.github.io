Components are the basic data unit of Rljson. A components table holds rows
of plain JSON values. Every row carries a hash of its content, and that hash
is the row's primary key: other rows refer to it by its hash.

In this tutorial you build a car catalog. It stores manufacturers, cars and
their wheels in three components tables, links them by references, validates
them and lists every wheel with its car and manufacturer.

You will learn how to:

- create a components table and hash it with `hip`
- refer to a row of another table by its hash
- validate an Rljson object with `Validate` and `BaseValidator`
- follow references to join the tables again

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir car-catalog
cd car-catalog
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `cars.ts`. Each of the following steps adds code to

A table is a JSON object with a few reserved fields:

| Field       | Meaning                                                                          |
| ----------- | -------------------------------------------------------------------------------- |
| `_type`     | The content type. For components tables, `components`                            |
| `_data`     | The rows                                                                         |
| `_hash`     | The hash of the table, calculated from all of its rows                           |
| `_tableCfg` | Optional: the hash of the [TableCfg](/guides/data_types/table-cfg/) of the table |

the object you pass to it. Afterwards every row and the table carry a `_hash`:

A hash is a SHA-256 hash of the content, encoded as base64url and shortened
to 22 characters. The `id` of a row is a name for you and your application;
Rljson itself identifies a row by its hash. The helper `ref` at the end of the
step reads the hash that `hip` has written into a row.

## 4. Understand the hashes

A hash depends on nothing but the content. Hash the same values again, even
with the keys in a different order, and you get the same hash:

<Snippet
  file="components.spec.ts"
  region="same-content"
/>

`hip` also hashes nested objects. Each of them gets a `_hash` of its own,
and the hash of the parent includes it. That is why Rljson data is called
_deeply hashed_. This has three consequences:

- **Duplicates are easy to find.** Two rows with the same content have the
  same hash, so a store that is keyed by hash keeps them once.
- **Rows are immutable.** A changed row is a new row with a new hash.
- **Hashes need no server.** Every machine calculates the same hash for the
  same content, without any coordination.

`Validate` runs every validator you add and returns their errors, keyed by
the name of the validator. When no validator finds a problem, the result is
an empty object, and the application goes on.

`BaseValidator` checks the rules of the format. Among others:

- every hash matches its content
- table and column names are lower camel case
- table names do not end with `Ref`
- every table has a `_data` array
- the rows that layers, cakes, buffets and trees refer to exist
- tables with a TableCfg match it

It stops at the first rule that fails and reports the errors of that rule.

<Aside type="note">
  The base validator checks the references of a components table only for
  columns that a [TableCfg](/guides/data_types/table-cfg/) declares as
  references. Without one, it cannot tell that `manufacturersRef` is a
  reference.
</Aside>

## What you have learned

- A components table holds rows of JSON values in `_data` and declares its
  type in `_type`.
- `hip` writes a hash into every row and into the table. The hash is the
  primary key of a row.
- Equal content has an equal hash. A change creates a new row.
- A row refers to a row of another table by its hash, in a column that ends
  with `Ref`.
- `Validate` with `BaseValidator` checks the hashes, the names and the
  structure of an Rljson object.
