Slices allow to organize huge collections of objects. A **slice** is a
single object of a collection. A slice is identified by a **slice id**. A
data structure called `SliceIds` allows you to:

- create different sets of slices
- derive new sets of slices from existing ones

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir car-catalog
cd car-catalog
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `slices.ts`. Each of the following steps adds code to
it: put the imports of a step at the top of the file, and its code below the
code of the previous step. The complete file is shown at the end.

| Field    | Meaning                                                  |
| -------- | -------------------------------------------------------- |
| `base`   | Optional: the hash of a row of slice ids that it extends |
| `add`    | The slice ids that are added to the base                 |
| `remove` | Optional: the slice ids that are removed from the base   |

## What you have learned

- A slice is a single object of a catalog, and a slice id identifies it.
- A row of type `SliceIds` lists slice ids
- A `SliceIds` row can extend a base row and remove slice ids from it, so it stores
  only the difference.
- Rows of slice ids live in a table of type `sliceIds`.

Next, [Layers](/guides/data_types/layers/) assign components to the slice
ids.
