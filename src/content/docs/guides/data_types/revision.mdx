Rljson data is immutable. To change a row, you add a new row: it gets a new
hash, and every reference to the old row stays as it is. A revision records
such a change. It names the table, the old row, the new row and the time of
the change. Revisions are rows of a table of type `revisions`.

In this tutorial you correct the nutritional values of flour and sugar. You
keep both versions, record the corrections as revisions and print the
history of each ingredient. Along the way you write a validator of your own,
which checks that the rows a revision links exist.

You will learn how to:

- change data by adding a row instead of editing one
- record a change as a revision
- list the history of an element and find its newest version
- write a validator and run it together with `BaseValidator`

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir nutrition-history
cd nutrition-history
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `history.ts`. Each of the following steps adds code to it:
put the imports of a step at the top of the file, and its code below the code

| Field         | Meaning                                                       |
| ------------- | ------------------------------------------------------------- |

| `successor`   | The hash of the new row                                       |
| `timestamp`   | The UTC time of the change, here in milliseconds              |
| `id`          | Optional: the id of the element, to find all of its revisions |

## What you have learned

- Rows are never edited. A change is a new row with a new hash, and the old
  row stays valid.
- A revision links the old row, its `predecessor`, to the new row, its
  `successor`, with a timestamp and an optional `id`.
- Following the successors leads to the newest version of a row.
- A validator of your own implements `Validator` and runs next to
  `BaseValidator` in `Validate`.
