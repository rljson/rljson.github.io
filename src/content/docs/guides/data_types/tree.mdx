Trees store hierarchical data like nested components, file systems or
organization charts. Every node of a tree is a row of a table of type
`trees`. A parent refers to its children by their hashes, so the hash of the
root covers the whole tree.

In this tutorial you build a car from nested parts. Every part has a name
and can consist of sub parts: the Taycan consists of a body and a
drivetrain, the body of a door and a roof, the drivetrain of a battery and a
motor. You print the parts, replace the battery and see that the change adds
only the parts on the path from the battery to the root.

You will learn how to:

- create parts with and without sub parts with `hip`
- store the parts of a tree in a trees table
- walk a tree from its root
- change a tree without copying it
- build a tree from a plain object with `treeFromObject`

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir car-parts
cd car-parts
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.

## 2. Create the leaves

A part is a node of the tree. Its `meta` holds the `Part` with its name, its
`children` hold the hashes of its sub parts. Parts without sub parts are the
leaves of the tree:

<Snippet
  file="tree.spec.ts"
  region="leaves"
  title="parts.ts"
/>

Every node of a tree has four fields:

| Field      | Meaning                                                   |
| ---------- | --------------------------------------------------------- |
| `id`       | Optional: the name of the node, unique among its siblings |
| `isParent` | `true` if the node can have children                      |
| `meta`     | Any JSON data of the node, or `null`                      |
| `children` | The hashes of the children, or `null` for a leaf          |

The parts carry their name in `meta`, so they leave out `id`.

## 3. Create the parents

Parts that consist of sub parts are the parents. The body and the drivetrain
are the parents of the leaves, and the Taycan is the root above them:

<Snippet
  file="tree.spec.ts"

The hash of a parent includes the hashes of its children. That is why you
build a tree from the bottom up: first the sub parts, then the parts they
belong to. It also rules out cycles: a part that contains itself would have
to include its own hash. The validator reports such data as invalid hashes.

## 8. Build a tree from a plain object

`treeFromObject` turns a plain JavaScript object into hashed tree nodes. This
object describes the same car:

<Snippet
  file="tree.spec.ts"
  region="from-object"
/>

`treeFromObject` follows these rules:

- An object becomes a parent. Its keys are the ids of the children.
- An object with a `meta` key becomes a leaf with that `meta`.
- A value such as a string or a number becomes a leaf with
  `meta: { value }`.
- An array of objects with one key each becomes a parent whose children keep
  the order of the array. Any other array becomes a leaf with
  `meta: { value }`.
- A node with the id `root` is added on top, unless you pass `true` as the
  second argument.

Only leaves get a `meta`: the parents carry their name as `id`, and their
`meta` is `null`. So the nodes have the same structure as the parts you
built by hand, but different hashes. Use `treeFromObject` when only the
leaves carry data.

## What you have learned

- Every node of a tree is a row with `id`, `isParent`, `meta` and
  `children`. A part keeps its name in `meta` and its sub parts in
  `children`.
- A parent refers to its children by hash, so a tree is built from the
  leaves up, and the root hash covers the whole tree.
- A change adds new nodes on the path to the root and shares everything else.
- `treeFromObject` builds the nodes from a plain object.
