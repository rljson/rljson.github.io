A cake stacks layers. All layers of a cake cover the same slice ids, and
each of them assigns a different kind of component to them: one set of
slices, seen through several layers.

In this tutorial you build a wheel shop. Its summer setup for a car has two
slices, `front` and `rear`, and three layers: brakes, rims and tires. Then you
put together a winter setup that reuses the brakes and the rims and only
changes the tires.

You will learn how to:

- share one set of slice ids between several layers
- stack layers into a cake
- reuse layers in another cake
- resolve what each slice of a cake is made of

## 1. Set up the project

Create a project and install the core package and the hashing package:

```bash
mkdir wheel-shop
cd wheel-shop
echo '{ "type": "module" }' > package.json
pnpm add @rljson/rljson @rljson/hash
```

`"type": "module"` lets the application use ES modules and top-level `await`.
Now create the file `wheels.ts`. Each of the following steps adds code to it:
put the imports of a step at the top of the file, and its code below the code
of the previous step. The complete file is shown at the end.

## 5. Stack the layers into a wheel setup

A cake names its slice ids and maps the name of each layers table to the hash
of one layer in it:

<Snippet
  file="cake.spec.ts"
  region="cake"
  title="wheels.ts"
/>

| Field           | Meaning                                                   |
| --------------- | --------------------------------------------------------- |
| `sliceIdsTable` | The name of the table with the slice ids                  |
| `sliceIdsRow`   | The hash of the row that lists the slice ids of the cake  |
| `layers`        | Maps the name of each layers table to the hash of a layer |
| `id`            | Optional: the name of the cake                            |

Since `layers` is keyed by table, a cake takes at most one layer from each
layers table. That is why the brakes, the rims and the tires each get a
layers table of their own. Note that the row of slice ids is called
`sliceIdsRow` here, while a layer calls it `sliceIdsTableRow`.

For every cake, `BaseValidator` checks that the table of slice ids and the

referenced layer. It also checks each layer, as described in

  The validator does not check that the layers of a cake use the slice ids of

## What you have learned

- A cake names a row of slice ids and one layer from each of several layers
  tables.
- All layers of a cake assign their components to the same slice ids.
- A cake refers to its layers by hash, so another cake can reuse them.
- To find out what goes onto a slice, follow each layer of the cake to the
  component it assigns to that slice.
